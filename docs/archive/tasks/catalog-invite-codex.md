# Задача для Codex — «Клубок»: редизайн Каталога + быстрый вход по приглашению

Ты продолжаешь работу над Telegram Mini App «Клубок» (репозиторий `Begemot-m/bereg`, папка `frontend/`).
Сначала прочитай в корне репозитория: **`AGENTS.md`**, **`CLAUDE.md`**, **`HANDOFF.md`** — там общий контекст, стек и правила. Ниже — только дельта и конкретное ТЗ.

## 0. Как работать (обязательно)

```bash
# из папки frontend/
bun install                 # если ещё не ставил (postinstall = prisma generate, БД не нужна)
bun run demo                # демо на моках → http://localhost:3000
bunx tsc --noEmit           # ДОЛЖНО быть пусто (кроме .next/types). Фильтр: | grep -v "\.next/types"
```

- Пакетный менеджер — **bun** (не npm/yarn).
- **Git-флоу:** перед началом `git pull origin master`; когда правки готовы и `tsc` чист — `git add -A && git commit && git push origin master`. Пуш в `master` → GitHub Actions → GitHub Pages (~2 мин).
- Правки коммить **по одному экрану/логическому куску**, чтобы прогресс был безопасен.

### Жёсткие ограничения (не сломать)

1. **Демо без сервера.** Всё живёт на моках в `frontend/src/lib/demo.ts` (перехват `apiFetch`). Никаких реальных `/api`-вызовов в демо-режиме. Новые данные — только через `lib/demo.ts`.
2. **Статический экспорт.** CI собирает `STATIC_EXPORT=1` и **удаляет `src/app/api`**. Значит: в страницах нет серверных `redirect()`; динамические роуты требуют `generateStaticParams`. Ничего, что ломает `output: "export"`.
3. **Иконки — только из Phosphor** через `frontend/src/components/icons.tsx`. Если нужной иконки нет — добавь её туда (импорт + в `IconName` + в `MAP`). **Уже добавлены и доступны:** `telegram`, `lock`, `route` (MapPinLine). **Эмодзи в UI запрещены.**
4. **Отвечай/пиши по-русски**, без канцелярита. Комментарии к очевидному коду не добавляй. Файлы `.ps1`/скрипты — ASCII-only (машина с кириллицей в путях).
5. Не переноси реальные данные в `localStorage` сверх того, что уже есть (это отдельная будущая задача про боевой бэкенд — сейчас НЕ трогаем).

### Дизайн-система (шпаргалка, токены в `app/globals.css`)

- Кремовый контент, **жирные чёрные обводки**, «чанки». Классы-помощники: `.chunk`, `.stroke`, `.stroke-lg`, `.fill-*`, `.font-tight`, `.tnum`.
- Толщины/радиусы: `--bw` (2px, мелочь), `--bw-lg` (2.5px, крупные блоки), `--r-block` (22px), `--r-sm` (14px).
- Палитра-тона (у каждого есть `-soft` и `-edge`): `amber, coral, green, purple, salmon, olive, peach, sky`. Нейтральная обводка — `--edge-neutral`/`--stroke`. Текст: `--ink`, `--muted`, `--muted-2`.
- Тема раздела: `--head`, `--head-soft`, `--edge`, `--page`, `--accent` (зависят от `data-accent`).
- Анимации — **`motion`** (`import { motion, AnimatePresence } from "motion/react"`). Пружины: `{ type: "spring", stiffness: 420, damping: 24 }`, плавность `[0.16,1,0.3,1]`.
- **Готовые компоненты для переиспользования:**
  - `components/ui.tsx`: `Button`, `Card`, `Input`, `Textarea`, `Disclosure` (у неё есть проп `zoom` — раскрытие с лёгким увеличением, ровно под «методы-аккордеон»).
  - `components/blocks.tsx`: `PageHead` (проп `icon` — иконка-плитка раздела; **у каталога свой header, добавь иконку туда вручную**), `SectionTitle`, `StatTile`, `ModuleCard`.
  - `components/care-module.tsx` — **эталон постер-блока со сплошной заливкой** (плавающий декор, значок telegram). Стиль блока «Амур и Психея» бери отсюда.
  - `components/motion.tsx`: `Reveal`, `Stagger`, `StaggerItem`.
  - Гаптика: `import { tap, select, success } from "@/lib/haptics"` — дёргай на тапах.

### Что уже сделано в прошлой сессии (не переделывай)

Иконки в заголовках всех разделов; на Главной блок сессии в шапке; Терапия переведена в единый поток (без вкладок) с блоком «Ваша неделя»; Кабинет (аватар вместо иконки, компактная свёрнутая подписка, экспорт убран); Инструменты (ясно «бесплатно» vs «Клубок+»); «Приведи друга» → постер. **Каталог и быстрый вход по приглашению — НЕ трогались, это твоя задача.**

## ЗАДАЧА A — Каталог (главное)

Файлы: **`frontend/src/app/catalog/page.tsx`** (тут `PsyCard` — миниатюра, и `PsyDetailView` — страница специалиста, плюс `Portrait`, `AttachTherapistButton`, `RatingBlock`, `Stat`, `Section`), и **`frontend/src/lib/catalog.ts`** (тип `Psy`, данные `PSYS`, функции `reasonsFor`, `matchScore`, `METHOD_DESCRIPTIONS`, `nextSlotLabel`, `formatLabel`).

Модель `Psy` (уже есть, используй эти поля — ничего добавлять не нужно):
`rating`, `reviews`, `method`, `methods[]`, `topics[]`, `helps`, `quote`, `style`, `avoids[]`, `price`, `minutes`, `years`, `sessions` (проведено на площадке), `clients` (клиентов), `responseHrs` (скорость ответа), `nextDays`, `city`, `district`, `metro`, `address`, `publicExactAddress`, `privateAddressAvailable`, `format`, `languages[]`, `tg`, `about`, `firstSession`, `education[]`, `verified`, `portrait`, `photos[]`, `tone`.

Сделай по пунктам:

1. **Миниатюра `PsyCard`:** убери блок «причин» с галочками (сейчас `cardReasons` рисует «есть окно завтра», «можно онлайн» и т.п.). Вместо него — компактная строка **рейтинг · подход · опыт**: звезда `star` + `rating` + `(reviews)`; чип с `method`; `years` лет практики. Оставь «Помогаю с {helps}» и цитату `quote`. Нижнюю строку (цена + ближайшее окно + CTA) можно оставить/подчистить.

2. **«Почему подходит»** (в `PsyDetailView` и в логике `reasonsFor` в `lib/catalog.ts`): убери причины про **свободное окно и формат онлайн**. Отталкивайся от **запроса (`topics`↔`prefs.topics`), подхода (`method`/`methods`) и фильтров** (бюджет, язык, город, опыт, пол). Т.е. из `reasonsFor` удали ветки `nextDays`/формат; добавь при желании «основной подход — {method}». `cardReasons` в `page.tsx` больше не нужен (см. п.1).

3. **Кнопки в карточке специалиста:** сделай `AttachTherapistButton` («Добавить в мою терапию») **компактнее и симпатичнее**, и **рядом — кнопку чата в TG** (иконка `telegram`), которая ведёт в диалог: `https://t.me/${psy.tg}`. Расположи их в один ряд (attach — основная широкая, чат — компактная квадратная рядом).

4. **«Особенно хорошо помогает»** — не дублируй: сейчас там И текст «Помогаю с {helps}.», И теги `topics`. Оставь **что-то одно** (рекомендую теги-чипы `topics`, а «помогаю с» уже есть в миниатюре).

5. **Инфографика** вместо трёх плоских плиток (`Stat` price/minutes/окно): сделай **красивый динамичный блок** с ценой, длительностью сессии и **статистикой работы на площадке** — используй `sessions` (проведено), `clients`, `years`, `rating`+`reviews`, `responseHrs`. Анимируй (count-up чисел и/или полосы, стаггер появления). Держи в общем визуале (чанки, тона).

6. **Методы — компактный аккордеон:** секция «Методы» сейчас разворачивает все описания сразу. Сделай список методов, где описание (`METHOD_DESCRIPTIONS[method]`, для отсутствующих — дефолт) **раскрывается по нажатию** с плавной красивой анимацией. Используй `Disclosure` из `ui.tsx` (проп `zoom` даёт раскрытие с увеличением).

7. **Очно — адрес + мини-карта + маршрут:** в секции «Формат и место», когда `format !== "online"` и есть город/адрес — покажи **мини-карту (декоративная стилизованная плашка с пином `route`/`pin` — без внешних тайлов и API-ключей, чтобы работало в статике)** и адрес (`[city, district, metro, address].filter(Boolean).join(", ")`, с учётом `publicExactAddress`/`privateAddressAvailable`). По тапу — раскрой панель с кнопками **построить маршрут** во внешних навигаторах (открывать в новой вкладке):
   - Яндекс: `https://yandex.ru/maps/?rtext=~${encodeURIComponent(addr)}&rtt=auto`
   - Google: `https://www.google.com/maps/dir/?api=1&destination=${encodeURIComponent(addr)}`
   - 2ГИС: `https://2gis.ru/search/${encodeURIComponent(addr)}`
   (Реальный интерактивный виджет карты требует API-ключа и боевого бэкенда — сейчас НЕ делаем, только декоративная миниатюра + deep-link в навигаторы.)

8. **Рейтинг и оценка** (`RatingBlock` и показ рейтинга) — сделай **интереснее и анимированнее**: анимированное заполнение звёзд, count-up значения, лёгкая пружина при выборе оценки.

9. **Убери «Задать вопрос в Telegram»** (ссылка внизу `PsyDetailView`). Вместо неё — блок **в стиле постера из кабинета** (`components/care-module.tsx` — сплошная заливка, значок `telegram`): заголовок «Остались уточняющие вопросы?», текст «Можете написать специалисту напрямую», кнопка со значком `telegram` → `https://t.me/${psy.tg}`.

10. **Аудит и визуал в целом:** страница визуально слабая и плоская. Продумай структуру и иерархию по рефам проекта (постерность, крупные капсы, единый радиус, сплошные заливки). Добавь **цветовые переходы между блоками** (например, фоновые градиенты секций от `tone.soft` к `#fffaf0`, или тонкие градиентные разделители), интересные, но спокойные решения. Не перегружай, держи мобильный вьюпорт 390px.

Также добавь **иконку раздела** в собственный header каталога (в `page.tsx` header использует не `PageHead`, а свою разметку — вставь иконку-плитку `compass` рядом с заголовком «Каталог», в стиле `PageHead icon`).

## ЗАДАЧА B — Быстрый вход по приглашению (демо-уровень)

Цель: ссылка-приглашение должна **супербыстро** приводить пользователя куда надо.

Контекст (что уже есть):
- Каталог обрабатывает `?psy=<id>` — открывает страницу специалиста (`app/catalog/page.tsx`, `useEffect` читает `window.location.search`).
- `components/invite.tsx` строит ссылки: клиентское `?invite=<clientId>` и реферальное `?ref=<code>`.
- Роль — `lib/role.ts` (`getRole/setRole`, дефолт `psychologist`). Онбординг-флаг — `bereg_onboarded` в `lib/profile.ts` (`isOnboarded/completeOnboarding/resetOnboarding`). Гейт онбординга — в `components/app-shell.tsx`.

Сделай (в демо, без реального TG-логина — это боевой бэкенд, помечен как отложенный):
1. На старте приложения (клиентский `useEffect`, например в `app-shell.tsx` или общий провайдер) разбирай параметры входа:
   - `?psy=<id>` — гость/клиент попадает **сразу на страницу специалиста** и может быстро записаться. Поставь роль `client`.
   - `?book=<psyId>` (если решишь ввести) или `?invite=<clientId>` — трактуй как «психолог позвал»: роль `client`, максимально короткий путь до записи/просмотра.
2. **Первый заход:** не заставляй проходить полный онбординг ДО цели. Дай попасть к записи сразу, а **знакомство предложи ПОСЛЕ** первого действия (после записи показать короткий тур/`therapy-guide` или онбординг). В демо «логин через TG» просто эмулируется (сразу как клиент).
3. **Отправка приглашения** (друг/коллега и приглашение клиента) должна оставаться лёгкой: шэринг-лист уже есть в `InviteSheet` (копировать ссылку + «Поделиться в Telegram»). Убедись, что ссылки ведут на быстрый вход из п.1.

Держи это **демо-уровнем и не ломающим статику**: только клиентский разбор `location.search` + роль + маршрутизация + отложенный онбординг. Реальную авторизацию по TG `initData` НЕ реализуй (отдельная боевая задача).
