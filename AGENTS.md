# Хроника — контекст проекта для AI-агентов

Прочитай это перед работой. Проект ведётся несколькими AI-инструментами по очереди через git.
Рабочее название приложения — **«Хроника»** (бренд в `frontend/src/lib/brand.ts`). `bereg` — историческое имя репозитория, а ключи `bereg_*` в localStorage остались от прошлых названий: их не переименовываем, это сломает деплой и данные пользователей. Домен прода — `chronika.space`, и он единственный: других адресов у приложения нет, в ссылках и конфигах их быть не должно.

## Старт в новом чате

Владелец работает с нескольких компьютеров, в Claude Code и в Codex. Единственный источник
правды — git, не память инструмента. Порядок:

1. `git pull --ff-only` — **до** любых правок;
2. `git status` — посмотреть, не осталось ли незакоммиченного от прошлого инструмента;
3. прочитать этот файл целиком (он короткий) — раздел «ТЕКУЩАЯ ЗАДАЧА» ниже говорит, чем заняты сейчас;
4. **дальше читать только тот файл, который нужен под конкретную задачу**, а не все подряд:

   | Файл | Когда открывать |
   |---|---|
   | `CLAUDE.md` | только Claude Code — его локальные правила работы |
   | `PERFORMANCE-HANDOFF.md` | задача про скорость/аудит производительности |
   | `HANDOFF.md` | нужно понять, что уже сделано и что дальше по фичам |
   | `FEATURE-FLOW.md` | добавляем фичу с данными (демо-мок + боевой роут) |
   | `DESIGN-RULES.md` | правила стилей от владельца — первоисточник, короткий |
   | `DESIGN.md` | трогаем UI |
   | `RELEASE.md` / `UPDATES.md` | деплой, миграции, выкатка |
   | `BACKEND.md` | Prisma, API-роуты, база |

   Открыть все семь «на всякий случай» — это ~90 КБ в контексте до первой строчки кода. Не надо.

5. закончил правки — **одна команда, без вопросов и обсуждений**:

   ```bash
   cd frontend && bun run ship "что сделали"
   ```

   Она сама прогоняет `check`, коммитит, пушит, запускает сборку демо и падает,
   если что-то не сошлось. Спрашивать «коммитить ли?» не нужно: это часть
   задачи, а не отдельное решение. Незапушенная работа = следующий инструмент
   начнёт с устаревшей базы, а демо останется на старом коммите.
   Проверить, что доехало: `bun run deploy:status`.

   У Claude Code на это стоит страж: хук `Stop` (`.claude/hooks/unshipped.mjs`)
   не даёт закончить сессию, пока в `master` есть незакоммиченное или
   незапушенное.

Аудит воронки (`deploy/funnel.sql`, коммит `c4036bc`) показал: приходят почти

  только у ближайшего невыполненного. Состояние считает по живым данным
  (`work-hours` через `availabilityFromWorkHours`, `clients`, записи), когда всё
  сделано — исчезает совсем;
- **статистика работы в нулях больше не показывается** новичку (`app/page.tsx`):
  до первой записи её место занимает блок первых шагов;
- **пустой раздел «Клиенты»** отвечал «Нет клиентов в этом фильтре». Теперь при
  нуле клиентов — карточка «Здесь появятся ваши клиенты» с кнопкой, открывающей
  меню приглашения;
- **онбординг специалиста**: первый слайд теперь про свою практику («Ваша
  практика — в одном месте»), каталог сдвинут на третье место и обещает визитку,

  каталог на бесплатном тарифе честно помечен «14 дней» (`CATALOG_FREE_DAYS`),
  и сказано про 14 дней PRO после первой проведённой сессии.

Что напрашивается дальше по этому треку: письмо/уведомление на второй день без
клиента, лендинг с тем же обещанием, приглашение клиента одним касанием из
карточки первой сессии.

## Что это
«Хроника» — платформа для психологов (Telegram Mini App + веб). Три роли: **гость / клиент / психолог**. Психолог ведёт клиентов, записи, задаёт рабочие часы; клиент записывается в свободные окна. Центр-создатель — «Амур и Психея» (упомянут в кабинете). Живой прототип: https://begemot-m.github.io/bereg/

## Стек
- **Next.js 15 (App Router) + TypeScript**, фронт и бэк в одном проекте (`frontend/`).
- **Tailwind v4**, **motion** (framer-motion) для анимаций, **@phosphor-icons/react** для иконок.
- **Prisma + PostgreSQL** и API-роуты (`src/app/api`) — для боевого режима. НЕ используются в демо.
- **Демо-режим** (`NEXT_PUBLIC_DEMO=1`): всё работает в браузере на моках в `localStorage`, без бэкенда. Именно он задеплоен.

## Как запускать (папка frontend/)
```bash
bun install
bun run demo        # демо на моках → http://localhost:3000  (для разработки/просмотра)
bun run build       # прод-сборка
bunx tsc --noEmit   # проверка типов
```

## Деплой (важно)
Пуш в ветку `master` на GitHub (`Begemot-m/bereg`) → GitHub Actions собирает **статический экспорт** демо и публикует на GitHub Pages. Настроено в `.github/workflows/deploy.yml`.
- Статическая сборка: `STATIC_EXPORT=1 NEXT_PUBLIC_DEMO=1 PAGES_BASE_PATH=bereg`, CI удаляет `src/app/api` (в статике не нужен).
- `next.config.mjs` включает `output: "export"` и `basePath` только когда `STATIC_EXPORT=1`.
- Значит: **любая правка → git push → через ~2 мин на сайте**. Ломать статический экспорт нельзя (нет серверных `redirect()` в страницах, динамические роуты требуют `generateStaticParams`).
- **Пуш не считается выкаткой.** Бывало, что пуш не рождал сборку вовсе (зависшая очередь Pages), и демо неделю жило на старом коммите при зелёном локальном чеке. Поэтому вместо голого `git push`:
  ```bash
  cd frontend && bun run ship "что сделали"   # check + commit + push + сборка демо
  ```
  Внутри — `deploy:demo`: он пушит, явно запускает workflow (push-триггер в этом репозитории молчит) и двигает тег `demo-live` на выкаченный коммит. Молча «выкачено» больше не бывает.
- Проверить руками, что сейчас в демо: `curl -s https://begemot-m.github.io/bereg/version.json` — там `build` и `sha` выложенной сборки.
- Если сборка не появляется или висит в очереди — первым делом смотри https://www.githubstatus.com: при авариях Actions/Pages пуши перестают создавать сборки вообще. Скрипт такую аварию распознаёт и говорит прямо.
