# Продолжение работы на другом устройстве

Короткая инструкция, чтобы сесть за ноутбук (VS Code + Claude Code) и продолжить без потерь.
Общий контекст проекта — в [AGENTS.md](AGENTS.md). Правила для Claude — в [CLAUDE.md](CLAUDE.md) (оба уезжают вместе с репозиторием).

Живой прототип: https://begemot-m.github.io/bereg/

---

## 1. Что нужно на ноутбуке

- **Git**
- **Node.js 22.x или 24.x** (проверено на 22.14 и 24.18)
- **Bun 1.3+** — основной пакетный менеджер и запуск (`bun run …`)
- **GitHub CLI `gh`** — чтобы следить за деплоем (`gh auth login` при первом запуске)
- **VS Code + расширение Claude Code**
- *(опционально)* MCP-сервер **Playwright** — им проверяются правки глазами.
  Включается через `/mcp` в Claude Code. Без него правки проверяются только
  типами и сборкой, и часть визуальных ошибок проходит незамеченной.

## 2. Развернуть проект

```bash
git clone https://github.com/Begemot-m/bereg.git
cd bereg/frontend
bun install            # postinstall делает prisma generate — БД не нужна
bun run demo           # демо на моках → http://localhost:3000
```

Демо-режиму **не нужен `.env`** — всё живёт в localStorage браузера. `.env` (из `frontend/.env.example`) понадобится только для боевого бэкенда (Prisma/Postgres, ЮKassa, бот).

## 3. Рабочий цикл

```bash
git pull                                            # ВСЕГДА перед началом (репо ведут несколько инструментов)
# …правки…
cd frontend && bunx tsc --noEmit 2>&1 | grep -v "\.next/types"   # проверка типов, должно быть пусто
git add -A && git commit -m "…" && git push origin master        # пуш в master → авто-деплой
```

**Два деплоя, не путать:**

1. `deploy.yml` — демо на Pages. Пуш в `master` → статический экспорт
   (`STATIC_EXPORT=1 NEXT_PUBLIC_DEMO=1 PAGES_BASE_PATH=bereg`, CI удаляет
   `src/app/api`) → https://begemot-m.github.io/bereg/ (~2 мин).
2. `app-deploy.yml` — боевое приложение в Docker. Сборка (`build`) чинена и
   **проходит** (имя образа приведено к нижнему регистру `ghcr.io/begemot-m/bereg` —
   Docker-тег обязан быть lowercase). Шаг `deploy` (SSH-выкатка) пока падает:
   нужен сервер и секреты `SSH_HOST` / `SSH_USER` / `SSH_KEY`. Подробности — в
   [BACKEND.md](BACKEND.md).

Проследить за сборкой:

```bash
gh run watch $(gh run list --limit 1 --json databaseId -q '.[0].databaseId') --exit-status
```

**Проверка глазами.** Через MCP Playwright: `bun run demo`, вьюпорт 390×844.
Важно: скроллить нужно элемент `.overflow-y-auto`, а не window — страница
сама не прокручивается.

**Если правки «не применились»** — почти всегда кеш вебвью, а не сборка.
В Кабинете внизу показана дата сборки: старая дата = страница из кеша.
Лечится очисткой кеша Telegram и повторным открытием.

## 4. Что уже сделано (последние итерации)

- **Приложение переименовано в «Методика»** (было «Клубок»). Бренд — в `lib/brand.ts` (`APP_NAME`), в текстах хардкодов не осталось. «Вдох/Выдох» в дыхательных практиках — не бренд, не трогать.
- **Онбординг** (текущая версия): 4 цветных экрана-постера (амбер/зелёный/коралл/фиолет) с яркой заливкой, декоративными кругами, кикер-пилюлей, буллетами и **макетом экрана приложения в белой рамке телефона** (не персонажи — их убрали по просьбе). Пятый экран — выбор роли (фиолетовый залив сверху, кнопки ниже, под большой палец). Реальные скрины можно положить в `public/onboarding/intro-1..4.webp` — подхватятся, иначе показывается макет. Файл: `components/onboarding.tsx`.
- **Обучение по разделам с прожекторной подсветкой** — теперь **включено** и запускается **вручную**: на главной сверху ярко-лавандовый баннер-постер с игровым «!» («Обучение»). Флаг `TOUR_ENABLED` убран; запуск по событию `bereg:tour-start` (`startTour()`), тур монтируется в `app-shell`. Психолог — 5 шагов, клиент — 4. Повтор из Кабинета → «Пройти знакомство заново». Файлы: `components/room-tour.tsx`, баннер `TourBanner` в `app/page.tsx`.
- **Свежие правки этой сессии:** сессии — «Действия» над выбранными датами рядом с «Выбор» под календарём; календарь чётче (свободно=зелёный контур, занято=фиолет, сегодня=кольцо, выбран=тёмный) + плитки свободных окон зелёные везде; выбор дня сверху показывает весь день (`DayAgenda`). Главная психолога — убран блок «Что стоит подтянуть»; статистика работы — период «Неделя/Месяц/Всё». Карточка клиента — задания первыми, запись/перенос в стиле ленты окон (`SlotPicker variant="strip"`). Каталог — методы свёрнуты (раскрытие по нажатию), рейтинг переделан на круговой прогресс + анимированное распределение оценок.
- **Дизайн-система — в [DESIGN.md](DESIGN.md).** Там тон раздела и три его
  градации, пять правил (теней нет; безрамочный блок = цветная заливка, белый
  = рамка тоном раздела; вложенный блок без рамки; статусы и иконки без рамок;
  текст на заливке только белый или чернильный) и готовые классы `.card`,
  `.card-soft`, `.card-nested`, `.chip`, `.btn`, `.ico`, шкала `.t-*`.
  Правила включены глобально и действуют на инлайновые стили тоже —
  по файлам ходить не нужно, правится одним местом в `globals.css`.
  Исключение для конкретного элемента — класс `.keep-style`.
- **Терапия** пересобрана: настроение → «Работа со специалистом» (один блок
  со статистикой и заданиями, у задания одна кнопка «Выполнено») → «Доска
  для терапевта» (заметки с автосохранением, видны специалисту) → неделя →
  колесо. Записи снизу убраны.
- **Сессии**: календарь месяца разворачивается на всю шапку и сворачивает
  ленту дат; окна показывают длительность; отмена записи освобождает окно,
  а не удаляет его; в каждом дне плитка «+» с выбором времени, длительности
  и клиента (можно завести нового прямо там).
- **Каталог**: профиль специалиста — действия и рейтинг в шапке, постер с
  ценой, миниатюра записи с ближайшим окном, методы плиткой. Специальностей
  можно выбрать несколько, и они доезжают до каталога.
- **Экскурсия по разделам** — включена и запускается из баннера на главной
  (см. выше). `TOUR_ENABLED` больше нет.
- **Telegram**: полноэкранный режим (`requestFullscreen`), отступ под кнопку
  закрытия через `--top-pad`. Важно: `data-tma` ставится только когда
  `platform !== "unknown"` — скрипт Telegram создаёт `WebApp` и в браузере.
- **Метка сборки** в Кабинете → «О приложении»: по ней видно, свежая версия
  или из кеша.

Ключевые файлы: `app/globals.css` (токены и утилиты), `components/app-shell.tsx`,
`components/onboarding.tsx`, `components/room-tour.tsx`, `components/therapy-work.tsx`,
`components/week-windows.tsx`, `app/sessions/page.tsx`, `app/therapy/page.tsx`,
`app/clients/page.tsx`, `app/catalog/page.tsx`, `lib/demo.ts` (мок-бэкенд),
`lib/server/*` (сессии, аудит, окружение).

## 5.1. Дизайн-итерации: где остановились (29.07.2026)

Дизайн-система описана в **[DESIGN.md](DESIGN.md)** — сначала читать её.
Пройдены и закрыты: главная, каталог, терапия, кабинет, сессии, клиенты,
карточка клиента, инструменты. Из свежего, чего нет в DESIGN.md:

- `.x-close` — крестик закрытия, красный, во всём проекте.
- `DragScroll` (в layout) — горизонтальные ленты тянутся мышью и колесом;
  лента, которая не влезла, помечается `data-scrollable`, CSS даёт ей
  курсор-руку и подтаявший правый край. Стрелок для листания не рисуем.
- `VersionCheck` (в layout) + `out/version.json` из CI — приложение само
  замечает новую сборку и один раз перезагружается. Если снова прилетит
  «не обновляется», сначала проверить метку сборки в Кабинете.
- Календарь: свободный день — обводка, занятый — обводка с заливкой,
  выбранный — чёрная заливка. Подсветки «сегодня» нет намеренно.
- Бежевый как второстепенный фон выведен: `--surface-2` и `--edge-neutral`
  теперь серые. Тёплые тона самих разделов остались.

**Грабли, на которые уже наступали:**

- Глобальное правило «блок внутри блока — без рамки» действует на
  `.card/.card-soft/.card-plain/.panel/.panel-tint/.chunk`. Если обернуть
  в них редактор с осмысленными рамками (график, шкала, мини-неделя) —
  рамки исчезнут молча. Держать такой блок обычным `div` с инлайновой
  рамкой либо ставить детям `keep-style`.
- `--stroke` объявлен на `[data-accent]`, а не в `:root` — иначе застывает
  янтарным во всех разделах.

**Не сделано, ждёт очереди:** справка «Как это работает» (`help-deck.tsx`) —
мини-макеты и тексты описывают старый интерфейс (крестик, тумблер формата,
цвета окон). Нужно пройти по страницам справки и переписать под нынешний вид.

## 6. Что НЕ переносится через git (учти)

- Твой домашний `~/CLAUDE.md` — **заменён** на `CLAUDE.md` в репозитории (эта же папка), Claude Code на ноуте подхватит его сам.
- Память Claude Code (`~/.claude/projects/.../memory/`) — локальная для машины, для работы не нужна.
- Состояние демо в браузере (localStorage): онбординг и черновики — свои на каждом устройстве/браузере. Онбординг просто покажется заново — это нормально.
- **Секреты**: `deploy/.env` на сервере в git не лежит и не должен. Образец —
  `deploy/.env.example`.
- Первый запуск на ноуте: `gh auth login` (для деплой-логов), логин в Claude
  Code и, если нужна проверка глазами, `/mcp` → включить Playwright.

## 7. Чего делать не надо (проверено на своей шкуре)

- **Не собирать без `STATIC_EXPORT=1` и не думать, что проверил Pages.**
  Это две разные сборки. CI ещё и удаляет `src/app/api` — локально это
  повторяется копированием папки во временное место.
- **Не трогать `prisma db push`** на боевой базе. Только `migrate deploy`.
- **Не сносить блоки, которые «выглядят лишними»**, не сверившись: блок
  подписки в кабинете и плюсик в сессиях так уже удалялись по ошибке.
- **Не считать «не применилось» багом кода** до проверки даты сборки в
  Кабинете — трижды это оказывался кеш вебвью.
