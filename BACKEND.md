# Бэкенд «Клубка»: архитектура и путь к релизу

Документ описывает решение целиком: где хостимся, как храним ПД по 152-ФЗ,
как устроены вход и токены, как не потерять данные при обновлениях и сколько
это стоит. Дальше по нему идёт реализация.

---

## 1. Главное ограничение: 152-ФЗ

Оно определяет почти все решения, поэтому идёт первым.

**ПД граждан РФ должны храниться в базах на территории РФ** (ст. 18 ч. 5).
Отсюда прямое следствие: **Vercel, Supabase, Neon, PlanetScale, Firebase
и Railway отпадают.** Не потому что плохие — они физически вне РФ.

**Данные о состоянии здоровья — специальная категория** (ст. 10). Дневник
настроения, заметки для терапевта, колесо баланса, домашние задания — это
именно она. Требования жёстче обычных ПД: явное согласие, минимизация,
защита при хранении.

Что нужно сделать (инженерная часть — ниже; юридическую проверьте с юристом,
я не могу давать правовую оценку):

| Требование | Как закрываем |
|---|---|
| Хранение в РФ | Хостинг Timeweb Cloud / Selectel, регион РФ |
| Уведомление РКН | Подаётся до начала обработки, разово |
| Политика обработки ПД | Публичная страница + версия в коде (`POLICY_VERSION`) |
| Согласие на обработку | Таблица `Consent`: вид, версия документа, дата, IP |
| Отдельное согласие на данные о здоровье | `Consent.kind = "health"` |
| Право на удаление | `User.deletedAt` + фоновая очистка + запись в аудит |
| Право на выгрузку | Эндпоинт экспорта в JSON |
| Журналирование доступа | Таблица `AuditLog` — факты без содержимого ПД |

## 2. Хостинг и стоимость

Считаю на старт (до ~500 активных пользователей).

| Что | Где | ₽/мес |
|---|---|---|
| Приложение (Docker) | Timeweb Cloud VPS, 2 vCPU / 4 ГБ | 700–1 100 |
| PostgreSQL **managed** | Timeweb / Selectel | 1 500–2 500 |
| S3 для бэкапов и фото | Selectel (другой провайдер!) | 100–300 |
| Домен + TLS | reg.ru + Let's Encrypt | ~25 |
| **Итого** | | **≈ 2 500–4 000** |

**Почему managed PostgreSQL, а не своя на том же VPS.** Экономия 1 500 ₽
в месяц против: автоматических бэкапов, PITR, обновлений минорных версий и
мониторинга. Первая же потеря базы стоит дороже года экономии. Это тот
случай, где дешевле не значит бюджетнее.

**Почему бэкапы у другого провайдера.** Если скомпрометируют аккаунт
хостинга, бэкапы внутри того же аккаунта уйдут вместе с продом.

## 4. Вход и токены

### Два входа, один аккаунт

1. **Telegram Mini App** — `initData` проверяется HMAC-подписью бот-токена
   (уже реализовано в `lib/server/telegram.ts`, с `timingSafeEqual` и
   проверкой срока). Это первичный способ: аккаунт всегда рождается здесь.
2. **Веб** — вход по почте, которую пользователь привязал внутри мини-
   приложения. Одноразовый код на 6 цифр, живёт 10 минут, ограничение
   попыток. Почта без привязки в TMA войти не даёт — так веб не становится
   дырой в обход Telegram.

### Токены: что изменено и почему

Было: и access, и refresh — JWT, оба отдавались в JSON и жили в клиенте.
Такой refresh **невозможно отозвать** — «выйти со всех устройств» не
работает, украденный токен действует до истечения.

Стало:

- **Access** — короткий JWT (15 минут), в нём `userId` и `sessionId`.
- **Refresh** — случайные 32 байта. В базе лежит **только SHA-256 хэш**:
  утечка дампа не даёт войти.
- **Ротация**: каждый обмен выдаёт новый refresh, старый помечается
  заменённым.
- **Обнаружение кражи**: если предъявили уже заменённый токен — гасим всю
  цепочку (`familyId`). Вор и владелец выходят одновременно, владелец
  просто входит заново. Это стандарт OAuth 2.1 (refresh token rotation with
  reuse detection).
- **Куки httpOnly + Secure + SameSite=Lax** вместо JSON. XSS больше не
  уносит токен, а SameSite закрывает базовый CSRF. Для мутаций
  дополнительно проверяется `Origin`.
- Таблица `Session` хранит устройство, IP и время — отсюда экран «активные
  сессии» и «выйти везде».

## 5. Обновления без потери данных

Это то, ради чего писался пункт. Правила:

1. **Только `prisma migrate deploy`** в проде. Никогда `db push` —
   он молча приводит схему к желаемой и может снести колонку с данными.
2. **Миграции — часть репозитория** и проходят ревью как код.
3. **Бэкап перед миграцией** делается автоматически шагом деплоя.
   Не «обычно есть ночной», а именно перед этой миграцией.
4. **Разрушающие изменения — в два релиза.** Переименование колонки это:
   релиз 1 — добавить новую и писать в обе; релиз 2 — убрать старую.
   Между ними код работает с любой из версий схемы.
5. **Подписки и платежи не трогаем миграциями данных.** Состояние подписки
   — источник истины на стороне ЮKassa; локально это кэш, который
   восстанавливается запросом статуса платежа.

## 6. Бэкапы

- Managed PostgreSQL: снапшоты + PITR (штатно у провайдера).
- Плюс собственный `pg_dump` раз в сутки → S3 **другого** провайдера,
  хранение 30 дней, шифрование на клиенте.
- **Проверка восстановления раз в месяц** — по расписанию, с записью
  результата. Непроверенный бэкап не считается бэкапом.

## 7. Где обычно ломаются похожие проекты

Отдельным списком, потому что это и есть разница между «работает у меня»
и продуктом.

| Риск | Решение |
|---|---|
| Секрет с дефолтом (`?? "dev-secret"`) уезжает в прод | `assertEnv()` роняет контейнер при старте, если секрета нет |
| Токен в localStorage → XSS уносит аккаунт | Только httpOnly-куки |
| Нельзя отозвать сессию | Хэш refresh в БД + `revokeAllSessions` |
| Клиент передаёт чужой `id` и получает чужие данные | Каждый запрос фильтруется по `userId` из токена, никогда из тела |
| Нет валидации входа | Zod-схема на каждый эндпоинт |
| Перебор кодов/паролей | Лимит попыток на OTP + rate limit на auth-роуты |
| ПД в логах | В `AuditLog` пишем факт и контекст, не содержимое |
| Вебхук оплаты подделан | Проверка подписи ЮKassa + идемпотентность по `payment_id` |

```
DATABASE_URL=postgresql://…        # обязательна
TELEGRAM_BOT_TOKEN=…               # обязательна
JWT_SECRET=…                       # обязательна, ≥32 символов в проде
APP_URL=https://…                  # для писем и проверки Origin
POLICY_VERSION=2026-07-01          # версия политики обработки ПД
ACCESS_TTL_SECONDS=900
REFRESH_TTL_DAYS=60
```

В проде отсутствие первых трёх — падение при старте. Это осознанно.
